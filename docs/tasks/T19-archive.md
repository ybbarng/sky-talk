# T19 — 대화 내보내기와 되돌리기

**단계** 보관 · **상태** 속 완료 · 파일 어댑터와 화면 대기 · **먼저** T06

## 목표

**대화가 앱보다 오래 산다.** 아이폰 앱이 7일마다 만료되므로 이건 부가 기능이 아니라 필수다.

### 세 가지를 한 번에 만든다

| 형식 | 무엇에 | 되돌릴 수 있나 |
|---|---|---|
| `.skytalk.json` | 재설치 후 되돌리기 | **가능** |
| `.html` | 앱 없이 열어보기. 낙서까지 보인다 | 불가 |
| `.txt` | 어디서든 열리는 가장 단순한 형태 | 불가 |

**고르게 하지 않는다.** 사용자가 잘못 고를 수 있다. 한 번 누르면 세 개가 다 나오고 공유 창이 뜬다.

### 검증값이 핵심이다

```jsonc
"integrity": {
  "messageCount": 1523,
  "checksum": "sha256:...",     // 메시지 id를 정렬해 이은 값의 해시
  "firstMessageId": "01J...",
  "lastMessageId": "01J..."
}
```

되돌릴 때 다시 계산해 대조한다. 어긋나면 **멈추고 알린다.** 파일이 잘렸는데 모르고 넘어가는 일을 막는다.

### 큰 대화 다루기

메시지가 만 개를 넘어도 되어야 한다. **한 번에 다 읽지 않고 흘려가며** 쓰고 읽는다. 전부 메모리에 올리면 폰이 죽는다.

화면을 막지 않는다. 진행률을 보여준다.

### 되돌리기

```
파일 고르기 → 형식 확인 → 검증값 대조 → 한 건씩 넣기 → 결과 알리기
```

**겹쳐도 안전하다.** 같은 파일을 두 번 불러도 메시지가 두 배가 되지 않는다. id가 기준이다.

```
1,523건 중 1,200건을 새로 넣었어요.
323건은 이미 있었어요.
```

내 프로필까지 덮어쓸지는 **물어본다.** 상대 기기의 파일을 잘못 불러와 내 캐릭터가 바뀌는 일을 막는다.

### 자동 보관

- 앱이 뒤로 갈 때 확인해서 24시간이 지났으면 새로 만든다
- 앱 내부 **문서 폴더**에 저장한다. 아이폰에서 파일 앱으로 꺼낼 수 있는 위치다
- 최근 3개만 남긴다
- 화면을 막지 않는다

### 만료 전 알림 (아이폰) — 안 하기로 했다

원래는 설치한 지 4일이 지나면 앱을 열 때 한 번 알리려 했다. **안 만든다.**

7일을 넘겨 비행할 일이 없고, **대화 기록은 안드로이드에서 뽑는다.**
안드로이드에는 만료가 없으니 아이폰이 안 열려도 잃는 것이 없다. 비행 중에
"곧 앱이 안 열려요" 를 띄우면 겁만 주고 할 수 있는 것도 없다.

세는 함수(`shouldWarnAboutExpiry`, `expiryMessage`)와 테스트는 남겨뒀다.
사정이 바뀌어 아이폰에서도 뽑아야 하면 화면에 붙이기만 하면 된다.

### HTML 파일

앱 없이 열리는 한 장짜리 파일이다. 바깥에서 아무것도 불러오지 않는다(인터넷이 없을 수 있다).

- 날짜별로 정리된 대화
- 낙서는 SVG로 그대로 그린다
- 밝은/어두운 화면 둘 다 지원 (브라우저 설정을 따라간다)

## 테스트

- 만 건을 내보내고 다시 불러도 하나도 빠지거나 겹치지 않는다
- 같은 파일을 두 번 불러도 두 배가 되지 않는다
- 검증값이 어긋나면 멈춘다
- 파일이 잘렸을 때 알아챈다
- 다른 앱이 만든 JSON을 넣으면 거절한다
- 만 건 내보내기에서 메모리가 터지지 않는다
- HTML이 브라우저에서 열린다

## 끝난 걸 어떻게 아는가

- [ ] **아이폰 앱을 지우고 다시 깔아도 대화를 되돌릴 수 있다** (실제로 해본다)
- [ ] 만 건 내보내기가 5초 안에 끝난다
- [x] 만료 알림 — 안 만들기로 했다 (위에 이유를 적어뒀다)
- [ ] 여기까지 하면 아이폰 7일 문제가 해결된다 — **안드로이드에서 뽑는 것으로 갈음한다**

## 하면서 알게 된 것

### 꺼내다 만 파일은 스스로 앞뒤가 맞는다

가장 무서운 경우다. `streamAll` 은 행 하나를 해석하지 못하면 거기서 조용히 멈춘다.
그 자리에서는 실패를 알릴 길이 없기 때문이다. 그러면 **나머지가 없는 채로 멀쩡해
보이는 파일이 나온다.** 적힌 건수와 든 건수가 맞고, 검증값도 그 상태로 계산되니
되돌릴 때도 안 걸린다.

검증값은 이걸 못 잡는다. 파일 안의 값끼리만 맞춰보기 때문이다. 그래서 꺼내기
시작할 때 저장소가 답한 수(`sourceCount`)를 파일에 같이 적는다. **파일 바깥에서
온 수라서** 이것만이 단서가 된다.

예전 파일에는 이 값이 없다. 없으면 이 확인을 건너뛴다. 대화가 앱보다 오래 사는 게
목적인데, 새 검사를 들이면서 예전 파일을 못 열게 만들면 앞뒤가 안 맞는다.

### 검증값이 파일 끝에 온다

흘려가며 쓰는 것과 검증값을 앞에 두는 것은 같이 할 수 없다. 다 읽어봐야 알 수 있는
값이기 때문이다. JSON 은 자리 순서를 따지지 않아서 끝에 둬도 된다.

### 형식 만드는 코드를 application 에 뒀다

카드는 `infrastructure/archive/*Writer.ts` 를 적어뒀지만, 글자를 만드는 일은 순수
계산이라 기기에 기대는 것이 없다. infrastructure 에 두면 층 규칙 때문에 내보내기가
직접 쓸 수 없어 포트를 하나 더 만들어야 하는데, 얻는 것이 없다.

HTML 은 `check:tokens` 에서 뺐다. 브라우저는 `useTheme()` 을 모르니 CSS 에 실제
색을 적어야 한다. 값은 테마 토큰과 같게 맞춰 뒀다.

### 요약값을 직접 만들었다

`expo-crypto` 를 들이면 네이티브를 다시 빌드해야 한다. SHA-256 은 순수 계산이라
직접 만드는 값이 더 싸다. 스스로와만 맞춰보면 틀린 채로 늘 같은 값을 낼 수 있어서,
공개된 시험값과 Node 가 계산한 값 **양쪽**에 대고 확인했다.

### 아직 안 한 것

- 파일을 실제로 읽고 쓰는 어댑터 (`expo-file-system`, `expo-sharing`, `expo-document-picker`)
- 내보내기 화면 (`app/export.tsx`)
- 자동 보관, 만료 전 알림

전부 기기 모듈이 필요하다. 여행 전날에 네이티브를 다시 빌드하면 앱 자체가 없을
위험이 있어 미뤘다. 속은 다 만들어 뒀으니 어댑터만 붙이면 된다.
