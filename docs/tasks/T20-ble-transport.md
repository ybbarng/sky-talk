# T20 — 블루투스 보조 경로

**단계** 보조 · **상태** 완료 · 실기기 확인 2026-09-19 · 비행기에서 쓰는 주된 길 · **먼저** T09

## 목표

핫스팟을 못 쓰는 상황에서도 **글로는 대화할 수 있다.** 항공사가 개인 핫스팟을 금지할 수 있기 때문에 만든다.

## 근거

[04-transport-spec.md](../04-transport-spec.md) 4장 · [01-product-spec.md](../01-product-spec.md) C3

## 먼저 알아둘 것

**자주 쓰는 `react-native-ble-plx`는 찾는 쪽만 할 수 있다.** 알리는 쪽은 마땅한 라이브러리가 없어 **아이폰용 네이티브 모듈을 직접 만들어야 한다.** 이 공수 때문에 이 카드가 뒤로 밀려 있다.

## 할 일

```
modules/ble-peripheral/         직접 만드는 네이티브 모듈
  ios/BlePeripheralModule.swift    CBPeripheralManager. 200줄 안쪽
  src/index.ts

src/infrastructure/transport/ble/
  BleMessageTransport.ts
  BlePeripheral.ts          아이폰: 알린다
  BleCentral.ts             안드로이드: 찾는다
  chunk/
    Chunker.ts              긴 메시지를 조각내기
    Reassembler.ts          다시 붙이기
  Compressor.ts             보내기 전에 압축
```

### 역할

| | 역할 | 왜 |
|---|---|---|
| 아이폰 | 알리는 쪽 | iOS는 화면이 꺼져도 제한적으로 알림을 계속한다 |
| 안드로이드 | 찾는 쪽 | 안드로이드는 찾는 동작에 제약이 적다 |

Wi-Fi와 역할이 반대다. 각 운영체제가 잘하는 쪽에 맞췄다.

### 식별자

[04-transport-spec.md](../04-transport-spec.md) 4.2의 UUID 다섯 개를 그대로 쓴다.

### 조각내기

한 번에 보낼 수 있는 크기가 작다. 아이폰 185바이트, 안드로이드 최대 517바이트. 협상한 값에서 3바이트를 뺀 만큼씩 자른다.

```
┌────────┬────────┬────────┬─────────────────┐
│ 묶음번호│ 조각   │ 전체   │ 내용            │
│ 1바이트 │ 1바이트│ 1바이트│ 나머지          │
└────────┴────────┴────────┴─────────────────┘
```

- 한 메시지는 최대 255조각, 약 46 KB
- 보내기 전에 압축한다. 한국어는 절반 이하로 준다
- 마지막 조각 뒤 5초 안에 조립이 안 되면 그 묶음을 버린다

### 여기선 못 하는 것

명확히 막고 왜 안 되는지 알린다.

- **음성·영상**: 대역폭이 백분의 일이다. "지금은 글로만 이야기할 수 있어요"
- **낙서·사진**: 크기가 커서 대기시킨다. "Wi-Fi가 연결되면 보낼게요"
- **입력 중 표시**: 아예 보내지 않는다. 좁은 길을 실제 대화에 양보한다

### 속도

초당 2~5 KB다. 긴 글은 몇 초 걸린다. 화면에 보내는 중 표시를 띄운다.

## 테스트

**컴퓨터에서**
- 조각내고 다시 붙이면 원래 값과 같다 (여러 크기로)
- 조각 하나가 안 오면 그 묶음을 버린다
- 조각이 뒤바뀌어 와도 올바로 붙는다
- 압축하고 풀면 원래 값과 같다
- 46 KB를 넘으면 거절한다
- 블루투스 상태에서 음성·낙서·사진이 막힌다

**실제 기기로**
- 두 폰이 블루투스로 붙는다
- 글이 오간다
- Wi-Fi가 열리면 자동으로 갈아탄다 (T09)

## 끝난 걸 어떻게 아는가

- [x] 핫스팟 없이 블루투스만으로 대화가 된다 — 2026-09-19 비행기 모드 + 블루투스, 아이폰↔안드로이드
- [ ] Wi-Fi가 열리면 메시지를 흘리지 않고 갈아탄다 — 시험으로만 확인. 기기로는 안 해봤다
- [x] 못 하는 기능이 명확히 막히고 이유가 설명된다 — 막지 않고 **느리게 보낸다.** 사진은
      크기를 고르며 걸리는 시간을 보고, 음성은 20초까지. 통화만 안 되고 도움말에 적혀 있다

## 하면서 알게 된 것

### 2026-09-19 — 하루 종일 여기 있었다

"보조 경로" 로 만든 것이 비행기에서 쓰는 **유일한** 길이 됐다. 비행기 모드에서 핫스팟이
안 켜지기 때문이다. 아침에는 두 폰이 아예 안 붙었다. 순서대로 잡은 것:

1. **아이폰 스캔이 `Unknown` 상태에서 시작해 바로 실패했다.** 실패를 "블루투스 없음" 으로
   읽고 역할을 뒤집어 둘 다 알리는 쪽이 됐다. `PoweredOn` 을 기다린 뒤 뒤진다.
2. **Kotlin 쪽 쌓아두는 줄이 경합했다** (`ArrayDeque is empty`). 조각이 빠졌다. `synchronized`.
3. **받는 쪽이 `expect()` 를 안 불러 조각을 버렸다.** 인사 뒤에 빠진 것을 다시 달라고 한다.
4. **아무 기기나 GATT 서버에서 떨어지면 끊긴 걸로 쳤다.** 구독한 기기만 센다(`wasListening`).
5. **앱을 껐다 켜면 옛 연결이 남았다.** 아이폰은 이어졌다 하고 안드로이드는 기다렸다.
   알리기 시작할 때 남은 연결을 끊는다. 설정을 바꿀 때 `connect()` 를 다시 불러 상태가
   초기화되던 것도 이미 쓸 만하면 그냥 둔다.
6. **가만히 둬도 끊겼다.** 끊긴 걸 늦게 알았다. **심장박동**을 넣었다. 찾는 쪽이 10초마다
   빈 5바이트를 보내고 35초 동안 아무것도 안 오면 끊긴 것으로 보고 다시 뒤진다. 화면에는
   안 보인다. 한쪽만 보내므로 무한 핑퐁이 없다.
7. **bitchat 이 두 폰에 떠 있으면 안 붙었다.** 같은 연결을 나눠 쓴다. 지우지 말고 완전히
   끈다. 도움말과 연결 상세에 적었다.

### 사진과 음성을 막지 않고 흘려보냈다

처음에는 블루투스에서 자산 조각을 아예 안 보내 사진이 흐린 미리보기 한 장만 갔다.
사용자는 "설명하고 고르게 하라" 고 했다. 그래서:

- 머리를 5바이트(묶음 1, 순서 2, 전체 2)로 늘려 조각 65535개까지.
- `writeCharacteristicWithResponseForService` 로 하나씩 확인받으며 쓰고, 안드로이드 쪽
  줄이 12개를 넘으면 쉰다(`queued()`). 그래야 사이사이에 글이 끼어든다.
- 보내는 쪽·받는 쪽 모두 몇 퍼센트인지 실시간으로 (`onReceiveProgress`, `send(…, onProgress)`).
- 사진 크기 셋(작게·중간·원본)과 예상 시간을 고르는 창. 초당 3000바이트로 잡는다.
- 예전에 다 받은 사진에 0% 가 우르르 뜨던 것은 이미 있는 자산을 다시 안 기다리게 해서 고쳤다.
