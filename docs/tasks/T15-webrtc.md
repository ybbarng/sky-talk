### 서버를 안 쓰는 이유와 방법

```ts
new RTCPeerConnection({ iceServers: [], iceCandidatePoolSize: 0 })
```

같은 Wi-Fi 안이라 서로의 사설 주소로 바로 닿는다. 바깥 주소를 알아낼 필요가 없으므로 STUN과 TURN이 통째로 필요 없다. 협상 정보는 이미 열려 있는 TCP 연결(T09)로 주고받는다.

### 후보 주소 거르기

기기가 내놓는 후보 중 **사설망 주소만 골라 쓴다.** 바깥으로 나가려는 후보는 어차피 인터넷이 없어 닿지 않으므로, 버려서 협상 시간을 아낀다.

```
쓴다:    192.168.x.x, 10.x.x.x, 172.16~31.x.x, 169.254.x.x
버린다:  그 외 전부
```

### 협상

```
거는 쪽 ─ offer ────▶ 받는 쪽
       ◀─ answer ───
       ◀─ candidate ▶  (양쪽에서 여러 번)
```

- 10초 안에 연결이 안 되면 포기하고 이유를 알린다
- **블루투스로 붙어 있으면 통화를 열지 않는다.** 시도하기 전에 막고 왜 안 되는지 알린다
- 통화 중 Wi-Fi가 끊기면 통화는 끝난다. 블루투스로 이어갈 수 없다. 사용자에게 알린다

### 소리 설정

- Opus 코덱
- 한 방향 초당 24 kbit
- 20밀리초 단위로 잘라 보낸다
- 메아리 제거와 잡음 줄이기를 켠다. 비행기는 시끄럽다

### 소리 크기 내보내기

캐릭터 입을 움직이려면 상대 목소리의 크기가 필요하다(T10). 받는 소리의 크기를 0~1 값으로 계속 내보낸다.

## 테스트

기기가 필요한 부분과 아닌 부분을 나눈다.

**컴퓨터에서**
- 후보 거르기가 사설망 주소만 통과시킨다
- 협상 정보가 올바른 봉투로 오간다
- 10초가 지나면 포기한다
- 블루투스 상태에서는 통화를 시도조차 하지 않는다
- 통화 중 연결이 끊기면 통화가 정리된다 (자원이 남지 않는다)

**실제 기기로**
- 두 폰 사이에 목소리가 오간다
- 지연이 0.4초 이내다
