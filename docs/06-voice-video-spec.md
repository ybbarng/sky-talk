# 음성과 영상

> 상태: 계획 · 최종 수정 2026-09-19

## 0. 통화(음성·영상)는 준비 중이다 — 2026-09-19

**지금 앱에서 통화는 못 건다.** 이 문서의 1~6장은 통화가 생기면 지킬 계획이고,
실제로 쓰이는 것은 **7장 음성 메시지**뿐이다.

| | 지금 상태 |
|---|---|
| 통화 걸기 | **없다.** 통화 탭과 머리글의 통화 단추를 2026-09-19 에 뺐다 |
| 걸려오는 통화 | 받는 창(`CallOverlay`)만 남아 있다. 옛 앱이 걸어오면 뜬다 |
| 블루투스에서 | 어차피 안 된다. 대역폭이 백분의 일이다 |
| 협상 코드 | `WebRtcVoiceLink` 는 조립해 두지만 걸 단추가 없어 걸리는 일이 없다 |
| 도움말 | "아직 준비 중이에요. 블루투스로는 목소리를 나를 수 없어요" |
| 통화가 실패하면 | "소리를 잇지 못했어요. 통화는 집에서 Wi-Fi 로 이었을 때만 돼요" |

왜 빼는가: 비행기에서 쓰는 길이 블루투스뿐이라(04 문서 1.1) 통화 단추는 **눌러도
안 되는 단추**였다. 안 되는 단추는 없는 것보다 나쁘다. 눌러보고 앱이 고장났다고
생각한다.

떨어져 앉아도 목소리를 들려주는 일은 **음성 메시지**(7장)가 맡는다. 상대가 지금
듣고 있지 않아도 되고, 끊겨 있어도 보내둘 수 있어서 세 시간 비행에서는 이쪽이
더 자주 쓰인다.

---

이 문서의 절반은 **"음악을 들으면서 대화한다"** 는 요구 하나를 다룬다. 겉보기와 달리 이 앱에서 가장 까다로운 부분이고, 물리적으로 양보해야 하는 지점이 있다.

## 1. 통화를 여는 법 (계획)

### 서버 없이 WebRTC 쓰기

WebRTC는 보통 바깥 서버 두 개가 필요하다. 우리는 둘 다 없앤다.

| 보통 필요한 것 | 하는 일 | 우리가 대신 쓰는 것 |
|---|---|---|
| 시그널링 서버 | 두 기기가 서로의 주소를 주고받게 중개 | 이미 열려 있는 우리 TCP 연결 |
| STUN / TURN | 공유기 뒤 기기의 바깥 주소 알아내기 | **필요 없음.** 같은 사설망이라 서로의 주소로 바로 닿는다 |

```ts
new RTCPeerConnection({
  iceServers: [],              // 하나도 안 쓴다
  iceCandidatePoolSize: 0,
})
```

같은 Wi-Fi 안에서는 기기가 자기 사설 주소를 후보로 내놓고(host candidate), 그것만으로 연결이 완성된다. 인터넷이 필요한 부분이 통째로 사라진다.

### 협상 절차

```
거는 쪽                                받는 쪽
   │                                      │
   │─ call_signal { offer } ─────────────▶│
   │                                      │  (수락 화면)
   │◀─ call_signal { answer } ────────────│
   │                                      │
   │◀── call_signal { candidate } ───────▶│  (양쪽에서 여러 번)
   │                                      │
   │        소리와 영상이 흐른다            │
```

- 협상 정보는 **길 A(Wi-Fi)의 TCP 연결**로만 오간다. 블루투스로는 통화를 열 수 없다.
- 후보 주소 중 **사설망 주소만 골라 쓴다.** 바깥으로 나가려는 후보는 어차피 닿지 않으므로 버려서 시간을 아낀다.
- 10초 안에 연결이 안 되면 포기하고 이유를 알린다.

### 소리를 담는 방식

- 코덱은 **Opus**를 쓴다. 좁은 길에서도 목소리가 또렷하다.
- 한 방향에 초당 24 kbit 정도면 충분하다. 사설 Wi-Fi에서는 남아돈다.
- 20밀리초 단위로 잘라 보낸다. 짧을수록 지연이 줄지만 그만큼 자주 보내야 한다. 20은 그 사이의 통상적인 값이다.

## 2. 음악을 들으면서 대화하기

### 2.1 무엇이 문제인가

무선 이어폰은 **소리를 받기만 할 때**와 **말도 같이 할 때** 서로 다른 방식으로 동작한다.

| | 듣기만 할 때 (A2DP) | 말도 할 때 (HFP) |
|---|---|---|
| 음질 | 좋다. 음악용 | 나쁘다. 전화 음성용 |
| 소리의 폭 | 넓다 | 좁다 (사람 목소리 대역만) |
| 방향 | 이어폰으로 나가기만 | 나가고 들어오고 |

**마이크를 켜는 순간 이어폰이 나쁜 쪽으로 넘어간다.** 이건 이어폰과 운영체제가 정하는 일이라 앱이 거스를 수 없다. 에어팟 프로도, 버즈 프로도 마찬가지다.

즉 "음악을 좋은 음질로 들으면서 동시에 이어폰 마이크로 말하기"는 **기술적으로 불가능하다.** 둘 중 하나를 골라야 한다.

### 2.2 그래서 이렇게 한다

세 가지 방식을 만들고 **사용자가 고르게** 한다.

> 2026-09-19 에 바꿨다. **고르는 화면을 없앴다.** 첫 실행의 세 번째 쪽(말하기 방식
> 고르기)과 설정의 "소리" 절을 뺐다. 통화가 없는데 통화용 설정이 먼저 나오니
> 첫 실행이 길어지기만 했다. 저장된 값(`audioMode`, 기본 `push-to-talk-brief`)은
> 옛 설정 파일을 읽을 수 있게 형식에만 남겨 두었다. 통화가 생기면 그때 다시 띄운다.

#### 방식 1 — 말할 때만 잠깐 (기본값, 누르고 말하기)

```
평소:        음악 ────▶ 이어폰 (좋은 음질)
              마이크 꺼짐

버튼 누름:    음악 ──(작아짐)──▶ 이어폰 (잠시 나쁜 음질)
              마이크 켜짐 ──────▶ 상대

버튼 뗌:      음악 ────▶ 이어폰 (다시 좋은 음질)
              마이크 꺼짐
```

말하는 동안만 음질이 떨어지고, 손을 떼면 바로 돌아온다. 대부분의 시간 동안 음악이 온전하다.
**가장 추천하는 방식이고 앱의 기본값이다.**

#### 방식 2 — 폰 마이크로 말하기 (항상 열기 + 좋은 음질)

```
음악 ────▶ 이어폰 (계속 좋은 음질)
폰 내장 마이크 ────▶ 상대
```

이어폰 마이크를 포기하고 **폰에 대고 말한다.** 이어폰은 듣기 전용으로 남으므로 음악이 계속 좋은 음질이다.

비행기는 시끄러우니 폰을 입 가까이 들어야 한다. 대신 마이크가 계속 열려 있어 버튼을 누를 필요가 없다.

#### 방식 3 — 전화처럼 (항상 열기 + 이어폰 마이크)

이어폰으로 듣고 말한다. 편하지만 **음악 음질이 통화 내내 떨어진다.** 음악을 안 듣고 대화만 할 때 고르면 된다.

### 2.3 상대가 말하면 음악이 작아진다

어떤 방식이든 상대 목소리가 들어오면 음악을 자동으로 줄인다.

- 목소리가 시작되면 **0.2초에 걸쳐 25%까지** 줄인다. 뚝 끊기지 않게 서서히 줄인다.
- 목소리가 멎고 **0.8초 뒤** 원래 크기로 되돌린다. 문장 사이 짧은 침묵마다 음악이 오르내리는 걸 막는다.
- 이 동작은 앱이 음악 앱을 조종하는 게 아니라, 운영체제에 "내 소리를 낼 동안 다른 소리를 줄여달라"고 요청하는 방식이다.

### 2.4 운영체제별로 하는 일

**아이폰**

```
소리 종류(category):  playAndRecord      듣고 말하기
모드(mode):          voiceChat          통화용 (메아리 제거가 켜진다)
함께 주는 조건:
  · mixWithOthers     다른 앱 소리를 끄지 않는다  ← 음악이 살아남는 이유
  · duckOthers        내 소리가 날 때 다른 소리를 줄인다
  · allowBluetoothA2DP  이어폰으로 좋은 음질 출력을 허용
  · allowBluetoothHFP   (방식 1·3에서만) 이어폰 마이크 허용
```

방식 2에서 **`allowBluetoothHFP`를 빼는 것**이 핵심이다. 이러면 iOS가 이어폰 마이크를 후보에서 제외하고 폰 내장 마이크를 쓴다. 이어폰은 출력 전용으로 남아 좋은 음질을 유지한다.

방식 1에서는 버튼을 누를 때 소리 설정을 바꾸고 뗄 때 되돌린다. 바꾸는 데 0.1초 남짓 걸리므로, **버튼을 누른 직후 짧은 소리를 내어** 준비가 됐음을 알린다. 그 소리가 나기 전에 말하면 앞부분이 잘린다.

**안드로이드**

```
소리 용도:        USAGE_VOICE_COMMUNICATION
소리 내용:        CONTENT_TYPE_SPEECH
다른 앱에 요청:   AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK
                 (내 소리 날 동안 네 소리를 줄여달라. 끄지는 말고)
통신용 기기 지정: 방식 2에서는 폰 내장 마이크로 고정
```

안드로이드 12부터 통신에 쓸 기기를 앱이 직접 고를 수 있다. 방식 2는 이걸로 구현한다.

### 2.5 이어폰을 뺐다 꼈다 할 때

- 이어폰이 빠지면 **마이크를 즉시 끈다.** 스피커로 대화 내용이 새어나가는 걸 막는다. 화면에 "이어폰이 빠져서 마이크를 껐어요"라고 알린다.
- 다시 끼면 사용자가 켤 때까지 기다린다. 자동으로 켜지 않는다.
- 이어폰이 바뀌면(에어팟 → 헤드폰) 소리 설정을 다시 잡는다.

## 3. 두 가지 말하기 방식 (계획)

통화용이다. 통화가 없으니 지금은 아무 데도 안 쓰인다(0장). 음성 메시지는 이 방식이
아니라 **녹음 창**(7장)으로 한다.

### 누르고 말하기

- 버튼을 **누르는 동안만** 마이크가 열린다.
- 준비되면 짧은 소리와 진동으로 알린다. 그 다음에 말한다.
- 손을 떼면 0.3초 뒤에 닫는다. 말끝이 잘리지 않게 여유를 둔다.
- 버튼을 **위로 밀면 잠긴다.** 계속 누르고 있지 않아도 되고, 다시 누르면 풀린다. 긴 이야기를 할 때 손가락이 아프지 않다.
- 화면이 꺼져 있어도 **볼륨 버튼으로** 누르고 말하기가 되게 한다. 주머니에 넣은 채로도 쓸 수 있다.

### 항상 열기

- 마이크가 계속 열려 있다. 전화처럼 이야기한다.
- 소리가 없을 땐 전송을 멈춘다. 배터리와 대역폭을 아낀다.
- 잠시 마이크를 끄는 버튼이 늘 보인다. 껐는지 켰는지 화면에서 바로 알 수 있어야 한다.

### 바꾸기

통화 중에 언제든 바꿀 수 있다. 바꾸면 상대에게도 알려서 "지금 상대는 누르고 말하는 중"임을 화면에 표시한다. 상대가 왜 조용한지 몰라 답답한 상황을 막는다.

## 4. 화면을 꺼도 대화가 이어지려면

**아이폰**

`UIBackgroundModes`에 `audio`를 넣는다. 소리가 흐르는 동안에는 앱이 뒤로 가도 살아 있다.

- 소리가 완전히 멎으면 iOS가 앱을 재운다. 그래서 통화 중에는 **아주 작은 소리를 계속 흘려** 잠들지 않게 한다.
- 잠금 화면에 통화 중임을 표시한다.
- `voip` 배경 모드는 쓰지 않는다. 애플 푸시 서버가 필요한데 인터넷이 없어 무용하다.

**안드로이드**

통화 중에는 **앞에서 도는 서비스**(foreground service)를 띄운다. 알림 막대에 통화 중 표시가 남고, 시스템이 앱을 죽이지 않는다.

- 종류는 `microphone` + `mediaPlayback`으로 선언한다.
- 알림에서 바로 끊을 수 있게 한다.
- 배터리 절약 기능의 예외로 넣어달라고 한 번 요청한다. 거절해도 동작하지만 오래 켜두면 끊길 수 있음을 알린다.

## 5. 영상 통화

음성이 되면 영상은 트랙 하나를 더 얹는 일이다.

### 화질

| 상태 | 크기 | 초당 장면 | 대역폭 |
|---|---|---|---|
| 좋음 | 640×480 | 24 | 초당 600 kbit |
| 보통 | 480×360 | 20 | 초당 350 kbit |
| 나쁨 | 320×240 | 15 | 초당 180 kbit |

- 640×480에서 시작한다. 얼굴을 보는 용도라 이보다 클 이유가 없고, 전력을 덜 쓴다.
- 통신이 나빠지면 자동으로 낮춘다. 끊기는 것보다 흐린 게 낫다.
- 통신이 좋아지면 10초쯤 지켜본 뒤 올린다. 자주 오르내리면 더 거슬린다.

### 조작

- 앞뒤 카메라 바꾸기
- 영상만 잠시 끄기 (소리는 계속). 끄면 상대 화면에 내 캐릭터가 대신 뜬다.
- 내 얼굴 작은 화면은 끌어서 옮길 수 있고, 두 번 누르면 크게 바뀐다.

### 배터리

영상은 전력을 많이 쓴다.

- 시작할 때 "영상 통화는 배터리를 많이 씁니다"라고 한 번 알린다.
- 배터리가 20% 아래로 내려가면 영상을 끄자고 제안한다.
- 앱이 뒤로 가면 **내 영상 보내기를 자동으로 멈춘다.** 소리만 계속 간다. 앞으로 돌아오면 다시 보낸다.

## 6. 무엇이 잘못됐는지 알려주기

오류 코드를 띄우지 않는다. 무엇을 하면 되는지 적는다.

| 상황 | 화면에 뜨는 말 |
|---|---|
| 마이크 권한 없음 | 마이크를 쓸 수 없어요. 설정에서 허용해 주세요. |
| 통화가 되냐고 물으면(도움말) | 아직 준비 중이에요. 블루투스로는 목소리를 나를 수 없어요. 지금은 글·사진·음성 메시지로 이야기해 주세요 |
| 소리를 잇지 못함 | 소리를 잇지 못했어요. 통화는 집에서 Wi-Fi 로 이었을 때만 돼요. |
| 상대가 안 받음 | ○○님이 못 받았어요. 글로 먼저 말을 걸어보세요. |
| 상대가 거절 | ○○님이 지금은 받기 어려운가 봐요. 글로 말을 걸어보세요. |
| 통화 중 끊김 | 연결이 끊겨 통화가 끝났어요. 글은 계속 주고받을 수 있어요. |
| 이 앱에 통화 모듈이 없음 | 이 앱에서는 통화를 쓸 수 없어요. 글로는 그대로 이야기할 수 있어요. |

(2026-09-19 에 `presentation/copy/call.ts` 와 `app/help.tsx` 에 맞췄다. 옛 표의
"블루투스로 연결됨 → 지금은 글로만" 은 통화 단추가 없어지면서 뜰 자리가 없어졌다.)

소리와 관련된 것만 적는다.

### 녹음 창

**한 번 눌러 시작하고, 다시 눌러 끝낸다**(`VoiceRecordSheet`). 2026-09-19 에
"꾹 누르는 동안만" 에서 바꿨다. 누르고 있는 방식은 눌렸는지 안 눌렸는지 알 수 없어
놓친 줄 모르고 말을 했다.

1. 마이크 단추를 누르면 녹음이 시작되고 짧게 떨린다. "녹음 중 · N초" 가 오른다
2. 다시 누르면 끝난다. **20초가 되면 저절로 끝난다**(`MAX_VOICE_MS`)
3. 길이와 크기, 블루투스면 "약 N초 걸려요" 를 보여주고 **보내기 / 버리기** 를 고른다

### 소리 설정

| | 값 |
|---|---|
| 형식 | `.m4a`(AAC) |
| 표본 | 22.05kHz, 한 채널 |
| 비트레이트 | 32kbps — 10초에 40KB, 20초에 80KB |
| 녹음 중 다른 앱 소리 | `mixWithOthers`. 상대 음악은 안 끊긴다 |
| 마치면 | 마이크를 놓아준다. 잡고 있으면 음악이 계속 눌린 채로 남는다 |

녹음기는 `expo-audio` 의 `AudioModule.AudioRecorder` 를 쓸 때 불러온다. 맨 위에서
들여오지 않는다(모듈이 깨져도 글은 써야 한다).

### 받은 것을 들을 때

받은 파일은 사진과 같은 창고에 `<assetId>.jpg` 로 놓인다. 소리 재생기는 확장자로
형식을 고르므로 그대로는 못 튼다. **한 번 `.m4a` 로 복사해 두고 그것을 튼다**
(`withAudioExtension`). 2026-09-19 에 받는 쪽에서 재생이 안 되던 것을 이렇게 고쳤다.

"오면 바로 들려주기" 를 켜면 무전기가 된다. 규칙은 05 문서 "오면 바로 들려주기".
