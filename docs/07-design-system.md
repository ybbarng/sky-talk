# 디자인

> 상태: 확정 · 최종 수정 2026-09-19 (실기기로 두 폰을 맞춘 날의 화면 기준)

홈 화면에 보이는 앱 이름은 **SkyTalk** 이다. 패키지·번들 이름은 `skywalkie` 그대로다
([08-build-release.md](./08-build-release.md) 2.2).

## 1. 어떤 느낌으로 만드는가

**야간 비행기 객실.** 창밖은 어둡고, 머리 위 조명만 따뜻하게 켜져 있는 그 장면이다.

이 앱은 대부분 어두운 기내에서, 얼굴 가까이에서, 한 손으로 쓰인다. 그래서 이렇게 잡는다.

- **어두운 화면이 주인공이다.** 밝은 화면도 제대로 만들지만, 어두운 쪽을 먼저 그리고 밝은 쪽을 맞춘다.
- **두 사람의 색이 다르다.** 내 말과 상대 말이 색으로 구분된다. 따뜻한 색은 나, 서늘한 색은 상대다. 기내 조명과 창밖 하늘의 대비에서 가져왔다.
- **덜어낸다.** 두 명만 쓰는 앱이라 목록도 검색도 설정 더미도 필요 없다. 화면에 있는 것은 전부 지금 쓰는 것이다.
- **손가락이 닿는 곳은 크게.** 흔들리는 기내에서 좁은 좌석에 앉아 누른다. 누르는 영역은 최소 48pt다.

## 2. 색

색은 항상 토큰 이름으로 쓴다. `#RRGGBB`를 화면 코드에 직접 적지 않는다. 그래야 밝은 화면과 어두운 화면이 어긋나지 않는다.

### 어두운 화면

| 토큰 | 값 | 어디에 |
|---|---|---|
| `bg` | `#0B1020` | 화면 바탕. 심야 하늘 |
| `surface` | `#151B2E` | 카드, 말풍선 바탕 |
| `surfaceRaised` | `#1E2740` | 떠 있는 것. 시트, 메뉴 |
| `border` | `#2A3450` | 경계선 |
| `text` | `#E8ECF5` | 본문 |
| `textMuted` | `#8B95AD` | 시각, 보조 설명 |
| `textFaint` | `#5C6780` | 더 옅은 것 |
| `me` | `#FF9D5C` | **내 말.** 기내 조명 |
| `meText` | `#2A1408` | 내 말풍선 위의 글자 |
| `peer` | `#5CC8FF` | **상대 말.** 창밖 하늘 |
| `peerText` | `#04283D` | 상대 말풍선 위의 글자 |
| `success` | `#4ADE80` | 연결됨 (Wi-Fi 든 블루투스든) |
| `warning` | `#FBBF24` | 길을 옮기는 중, 곧 만료됨 |
| `danger` | `#F87171` | 끊김, 실패 |
| `onStatus` | `#0B1020` | 상태 색 위에 얹는 글자 |
| `overlay` | `rgba(4,8,20,0.72)` | 뒤를 가리는 막 |

### 밝은 화면

| 토큰 | 값 |
|---|---|
| `bg` | `#F6F8FC` |
| `surface` | `#FFFFFF` |
| `surfaceRaised` | `#FFFFFF` |
| `border` | `#E3E8F2` |
| `text` | `#121826` |
| `textMuted` | `#5D6A85` |
| `textFaint` | `#737E92` |
| `me` | `#C2410C` |
| `meText` | `#FFFFFF` |
| `peer` | `#0369A1` |
| `peerText` | `#FFFFFF` |
| `success` | `#16A34A` |
| `warning` | `#C2600A` |
| `danger` | `#DC2626` |
| `onStatus` | `#FFFFFF` |
| `overlay` | `rgba(18,24,38,0.4)` |

밝은 화면의 말풍선은 어두운 쪽보다 진하다. 흰 글자가 얹히기 때문이다. 연한 주황이나 하늘색으로 두면 글자가 읽히지 않는다.

### 어느 쪽을 쓸지

- 기본은 **기기 설정을 따라간다.**
- 설정에서 밝게 / 어둡게 / 기기 설정 따라가기 중에 고를 수 있다.
- 고른 값은 기기에 저장되어 다시 켜도 유지된다.
- 화면 전환은 0.2초에 걸쳐 부드럽게 바뀐다. 눈이 놀라지 않게.

### 읽기 쉬운지 확인하기

글자와 바탕의 대비는 최소 4.5대 1을 지킨다. 어두운 기내에서 화면 밝기를 낮춰도 읽혀야 한다. 이 값은 테스트(`colors.test.ts`)로 자동 확인한다.

기준을 나눠서 쓴다.

| 대상 | 기준 | 왜 |
|---|---|---|
| 본문 글자, 말풍선 글자 | 4.5 이상 | 읽어야 하는 것 |
| 아주 옅은 글자, 상태 색 | 3 이상 | 보조 정보 |
| 경계선 | 1.1 이상 | 장식이다. 글자 기준을 들이대면 어두운 화면이 그물처럼 보인다 |

**내 말과 상대 말의 구분은 대비로 재지 않는다.** 주황과 파랑은 밝기가 비슷해 대비가 1.1밖에 안 나오지만 실제로는 전혀 헷갈리지 않는다. 구분하는 건 밝기가 아니라 색이라서, 색상환에서의 거리로 잰다(120도 이상).

### 색을 직접 적지 못하게 막기

`pnpm check:tokens`가 `src/`와 `app/`에서 `#RRGGBB`나 `rgba(...)`를 찾아 실패시킨다. 색을 정의하는 `theme/` 폴더만 예외다. 한쪽 화면에서만 안 보이는 글자가 생기는 걸 막는다.

## 3. 글자

시스템 글꼴을 쓴다. 한국어가 가장 잘 읽히고 앱 크기가 늘지 않는다.

| 이름 | 크기 | 굵기 | 줄간격 | 어디에 |
|---|---|---|---|---|
| `display` | 34 | 700 | 40 | 첫 화면 제목 |
| `title` | 24 | 700 | 30 | 화면 제목 |
| `heading` | 18 | 600 | 24 | 구역 제목 |
| `body` | 16 | 400 | 23 | 메시지, 본문 |
| `bodyStrong` | 16 | 600 | 23 | 강조된 본문 |
| `caption` | 13 | 400 | 18 | 시각, 상태 |
| `label` | 12 | 600 | 16 | 작은 표지, 버튼 안 글자 |
| `mono` | 16 | 600 | 22 | IP 주소 같은 것 |

기기의 글자 크기 설정을 따라간다. 다만 너무 커져서 화면이 깨지지 않도록 1.3배까지만 늘린다.

## 4. 간격과 모서리

간격은 4의 배수만 쓴다.

```
xs 4    sm 8    md 12   lg 16   xl 24   2xl 32   3xl 48
```

모서리는 넉넉하게 굴린다. 부드러운 인상이 이 앱에 맞다.

```
sm 8    md 12   lg 16   xl 20   pill 999
```

말풍선은 `xl`(20)을 쓰되 **말하는 쪽 아래 모서리만 `sm`(8)** 으로 둔다. 말풍선이 어느 쪽에서 나왔는지 꼬리 없이도 알 수 있다.

## 5. 움직임

움직임은 정보를 전달할 때만 쓴다. 장식으로 쓰지 않는다.

| 상황 | 시간 | 방식 |
|---|---|---|
| 눌렀을 때 | 100ms | 0.96배로 줄었다 돌아옴 |
| 화면 전환 | 300ms | 부드럽게 (운영체제가 한다) |
| 연결 상태 바뀔 때 | 400ms | 색이 서서히 바뀜 |
| 사진 크게 보기 | 손짓 그대로 | 두 손가락으로 벌리고 끄는 만큼 |

기기에서 "동작 줄이기"를 켠 사람에게는 **움직임을 전부 없애고 즉시 바뀌게** 한다. 멀미가 나는 사람이 있고, 비행 중엔 더 그렇다.

### 쓰지 않는 움직임 — 실기기에서 잡은 규칙

- **`reanimated` 의 레이아웃 움직임(`entering`/`exiting`, 말풍선이 떠오르는 효과)을 쓰지 않는다.**
  그려지는 자리와 눌리는 자리가 어긋난다. 말풍선이 겹쳐 보였고, 설명 창의 단추가 안 눌려
  거기서 갇혔다. 기기에서 잰 어긋남이 220픽셀이었다. 손가락 손짓이 직접 끄는 값(사진
  확대)은 이와 다르므로 써도 된다.
- **`Modal` 을 직접 만들지 않는다. 반드시 `Sheet` 를 쓴다.** 안드로이드 edge-to-edge 에서
  자리가 어긋나고, 뒤를 가리는 막이 창 위까지 덮으면 단추를 가로챈다. `Sheet` 는 막이
  창과 겹치지 않게 위쪽 빈 자리만 차지하고, 안전 영역과 상태 표시줄을 처리해 둔다. 녹음
  창·설명 창·대화 비우기 확인이 전부 이것 위에 있다. 움직임은 운영체제의 `fade` 만 쓴다.

## 6. 캐릭터

### 왜 그림 파일이 아니라 코드로 그리는가

캐릭터는 가만히 있지 않는다. 상대가 말하면 입이 움직이고, 연결이 끊기면 시무룩해진다. 그림 파일로는 이런 변화를 만들 수 없다. 그래서 **SVG를 코드로 그린다.**

덤으로 어떤 화면 크기에서도 선명하고, 밝은 화면과 어두운 화면에서 색이 알아서 바뀌고, 앱 크기가 거의 늘지 않는다.

### 누가 누구를 보는가

첫 실행 때 자기 캐릭터를 고른다. 상대 화면에는 내가 고른 캐릭터가 뜬다.

```
   내 안드로이드 화면              여자친구 아이폰 화면
 ┌─────────────────┐            ┌─────────────────┐
 │   [여성 캐릭터]  │            │   [남성 캐릭터]  │
 │      상대        │            │      상대        │
 │                 │            │                 │
 │  말풍선(파랑)    │            │  말풍선(파랑)    │
 │      말풍선(주황)│            │      말풍선(주황)│
 └─────────────────┘            └─────────────────┘
```

기본값은 이 배치지만, 고르는 화면에서 자유롭게 바꿀 수 있다. 성별로 두 개만 두지 않고 몇 가지 더 준비한다.

### 준비하는 캐릭터

고르는 화면에 **넷씩 두 줄로 여덟**이 들어간다. 앞의 넷이 여성적, 뒤의 넷이
남성적으로 보이게 순서를 잡는다. 둘이 서로 다른 모습을 골라야 화면에서 누가
누군지 헷갈리지 않는다.

| 이름 | 생김새 |
|---|---|
| `aria` | 긴 머리, 헤드폰 |
| `nova` | 단발, 안경 |
| `luna` | 묶은 머리, 목도리 |
| `mira` | 물결지는 단발, 귀걸이 |
| `orion` | 짧은 머리, 이어폰 |
| `atlas` | 곱슬머리, 후드 |
| `kai` | 비니 모자 |
| `ren` | 뻗친 머리, 마이크 달린 헤드셋 |
| `pilot` | 조종사 모자. 숨겨둔 것이라 고르는 화면에 안 나온다 |

각 캐릭터는 같은 얼개 위에 머리 모양과 소품만 다르다. 그래야 표정 코드를 한 벌만 만들면 된다.

### 상대를 아직 모를 때

**상대가 무엇을 골랐는지는 인사(`hello`)를 주고받아야 안다.** 그런데 연결 화면은
바로 그 전에 뜬다. 그때 아무 캐릭터나 골라 그리면 **화면이 거짓말을 한다.** 여자친구가
한 번도 고른 적 없는 얼굴을 보고 "쟤가 저걸 골랐구나" 하게 된다.

그래서 모를 때는 모른다고 그린다. 같은 자리에 같은 크기로, 얼굴 대신 물음표가 있는
회색 그림자다. 자리는 지키되 누구인 척은 하지 않는다.

```
Character id={null}   →  얼굴 없는 그림자 (UnknownPeer)
Character id="mira"   →  지민이 고른 얼굴
```

한 번 이어지고 나면 `rememberPeer` 가 저장하므로, 다음부터는 앱을 켜자마자 진짜
얼굴이 뜬다. 모르는 것은 **첫 연결 전 딱 한 번뿐이다.**

이름도 마찬가지다. 모를 때는 "상대"라고 적고 "님"을 붙이지 않는다. 조사도 같이
갈린다 — 이름을 알면 "지민님이", 모르면 "상대가"다. `copy/connecting.ts` 의
`wordsFor` 가 이걸 한 곳에서 정한다.

### 표정

캐릭터는 지금 무슨 일이 일어나는지를 표정으로 알린다. **글씨를 읽지 않아도 상태를 알 수 있어야 한다.**

| 상태 | 생김새 |
|---|---|
| `idle` | 눈을 가끔 깜빡인다. 아주 천천히 숨 쉬듯 위아래로 움직인다 |
| `speaking` | 입이 소리 크기에 맞춰 움직인다 |
| `listening` | 살짝 고개를 기울인다 |
| `typing` | 머리 위에 점 세 개가 차례로 뛴다 |
| `disconnected` | 회색이 되고 눈이 반쯤 감긴다 |
| `sleeping` | 눈을 감고 머리 위에 Z가 뜬다. 상대 앱이 뒤로 갔을 때 |
| `videoOff` | 영상을 끈 자리에 대신 나타난다 |

입 모양은 실제 소리 크기를 받아 움직인다. 0에서 1 사이 값을 60분의 1초마다 받아 입을 벌리고 닫는다. 진짜로 말하는 것처럼 보이는 지점이 여기다.

### 어디에 나타나는가

- 대화 화면 맨 위 (작게, 이름과 상태 표시와 함께)
- 연결을 기다리는 화면 가운데 (졸다가 찾으면 또렷해진다)
- 첫 실행 때 고르는 화면
- 이모티콘 (내 캐릭터가 자세를 취한다)
- 통화 화면 (통화는 준비 중이라 지금은 안 뜬다)

### 대화 안의 이모티콘

**길게 누르면 무슨 뜻인지 옆에 뜬다.** 내 것이면 왼쪽 빈자리, 상대 것이면 오른쪽 빈자리다.
아래에 끼워 넣으면 목록이 밀려 스크롤이 움직이고 손가락에 가린다. 서랍에서 고를 때만
뜻이 보이면 받은 쪽은 팔짱 낀 게 "안 돼" 인지 "추워" 인지 알 길이 없다.

## 7. 아이콘

### 앱 아이콘

밤하늘 위에 **주황 여객기 옆모습**이 오른쪽을 향해 떠 있고, 창문 두 개가 켜져 있다. 그
두 창문 사이를 **크림색 봉투가 점선 호를 그리며 날아간다.** 떨어져 앉은 두 사람이 말을
주고받는 그림이다. 색은 기내 조명 주황(`me`), 크림색 종이, 밤하늘(`bg`)이다. 비행기가
화면 너비의 80% 쯤을 차지해서 48px 로 줄여도 "비행기와 편지" 로 읽힌다.

2026-09-19 에 시안 열둘(창문 사이 메시지 여섯, 동체에 TALK 여섯)을 만들어 고른 것이다.
처음 그림(봉투 위 실링 여객기)은 작게 줄이면 비행기가 안 보여 버렸다. 종이비행기와
초승달도 쓰지 않는다.

- 안드로이드는 앞뒤가 나뉜 형태(adaptive icon)다. 앞에는 비행기와 봉투(가운데 72% 안),
  뒤에는 밤하늘 그러데이션이 온다. 테마 아이콘(단색)은 비행기·봉투 실루엣과 점선 호다.
- 아이폰은 한 장으로 만든다. 모서리는 시스템이 알아서 자른다.
- **스플래시도 같은 비행기다.** 바탕은 앱 설정이 칠하고 그림만 준다. 아이콘을 바꾸면
  스플래시를 반드시 같이 바꾼다. 안 그러면 앱을 열 때 옛 그림이 잠깐 뜬다.
- 원본은 SVG(`assets/icon/*.svg`)로 그리고 `pnpm icons:generate` 로 뽑아낸다. 손으로 그린
  그림 파일을 두지 않는다. 네이티브에 넣는 법은 [08-build-release.md](./08-build-release.md) 2.2.

### 화면 안 아이콘

선으로 그린 아이콘을 쓴다. 굵기 1.75, 끝은 둥글게. 모든 아이콘을 SVG 컴포넌트로 직접 만든다. 라이브러리를 들이면 안 쓰는 아이콘 수백 개가 앱에 따라 들어온다.

**뜻이 바로 보이는 그림을 쓴다.** 느낌표·하트·말풍선을 도구 단추에 썼더니 무엇인지 헷갈린다고
했다. 지금은 콕 찌르기 = 찌르는 손가락(`poke`), 이모티콘 = 스마일 얼굴(`smile`),
낙서 = 팔레트(`palette`), 음성 재생 = 세모(`play`)·정지 = 네모(`stop`), 도구 열기 = 더하기(`plus`)다.
대화 화면 위의 비행기(`plane`)는 오른쪽을 향하게 돌려 그린다.

## 8. 처음 쓰는 사람을 위한 장치

> 제품 명세 F4에 대응한다. **말을 나눌 수 없는 두 사람이 각자 화면만 보고 연결에 성공해야 한다.**

### 물음표

화면의 중요한 요소 옆에는 작은 물음표가 있다. 누르면 그 자리에 한두 줄 설명이 뜬다.

```
┌────────────────────────────────┐
│ 누르고 말하기              (?) │
│                                │
│ 버튼을 누르는 동안만 마이크가   │
│ 켜져요. 손을 떼면 꺼집니다.     │
│ 음악을 들을 때 가장 좋아요.     │
│                        [알겠어요]│
└────────────────────────────────┘
```

설명 문구는 한곳에 모아둔다. 화면 코드 사이에 글이 흩어지면 고치기 어렵다.

### 첫 실행 안내

세 단계다. **역할을 고르게 하지 않는다.** 아이폰은 앱에서 핫스팟을 켤 수 없어서
선택지가 실질적으로 하나뿐이고, 물어보면 헷갈림만 는다. 안드로이드가 알리고
아이폰이 찾는다.

```
1. 시작하기                무엇을 하는 앱인지
2. 나를 어떻게 보여줄까요   캐릭터와 이름
3. 이어보기                블루투스만 켜면 된다는 것, 알림 권한
```

2026-09-19 에 두 단계를 뺐다. "말하기 방식 고르기" 는 통화가 없으니 의미가 없고,
"집에서는 Wi-Fi 로 더 많이" 카드는 자리에 앉은 사람에게 잠긴 핫스팟 메뉴만 들여다보게
했다. 각 단계에 그림을 넣는 일은 아직이다.

### 연결을 기다릴 때

**빙글빙글 도는 표시만 두면 앱이 멈춘 줄 안다.** 그렇다고 기술 상태를 늘어놓으면
읽을 수가 없다. 그래서 **사람이 보는 단계**로 옮겨 한 줄로 말한다.

| 단계 | 언제 | 할 일이 있나 |
|---|---|---|
| `need-hotspot` | 알리는 쪽인데 블루투스가 꺼져 있다 | 블루투스 켜러 가기 |
| `waiting-for-peer` | 켰고 상대를 기다린다 | |
| `need-wifi` | 찾는 쪽인데 블루투스가 꺼져 있다 | 블루투스 켜러 가기 |
| `looking` | 켰고 상대를 뒤지는 중 | |
| `found` | 찾았다 | |
| `joining` | 이어지는 중 | |
| `recovering` | 끊겨서 다시 붙는 중 | |

단계 이름에 핫스팟·Wi-Fi 가 남아 있지만 뜻은 둘 다 "블루투스가 꺼져 있다" 다. 이름을
바꾸면 시험까지 줄줄이 고쳐야 해서 뜻만 바꿨다. 캐릭터가 같이 말한다. 찾는 동안에는
졸고 있다가, 찾으면 또렷해진다. **글씨를 안 읽어도 상태를 알 수 있어야 한다.**

#### 블루투스가 꺼진 것을 가장 먼저 본다

한 번 이어진 뒤라도 마찬가지다. 블루투스가 꺼졌으면 아무리 기다려도 저절로
돌아오지 않는데, 여기서 "알아서 다시 이어드릴게요"라고 하면 **사람이 손을 놓고
기다리게 된다.** 사람이 켜야 풀리는 일은 사람에게 말해야 한다.

예전에는 Wi-Fi 사설망에 있는지로 판단했다. 비행기에서는 Wi-Fi 가 없는 것이 정상이라
멀쩡한 사람에게 켜라고 하게 됐다. 지금은 `react-native-ble-plx` 의 상태(`useBluetoothWatch`)로
본다. 아직 못 읽었을 때는 넘어간다. 모르는 것을 "꺼졌다"로 바꾸면 멀쩡한 사람에게
설정을 열라고 하게 된다. "켜러 가기" 는 블루투스 설정을 연다.

#### 쓰지 않는 것

- 기술 용어 — 게이트웨이, 브로드캐스트, IP, 소켓
- 진행 숫자 — "96/253"은 불안만 준다
- 물어보라는 말 — **물어볼 수 없는 상황을 위해 만든 앱이다**

한참 지나도 안 되면 그때 도움말을 덧붙인다. 처음부터 보여주면 "안 되나 보다"
싶어진다. 할 일이 이미 있는 단계에서는 띄우지 않는다. 버튼이 있는데 도움말까지
띄우면 화면이 시끄럽다.

**기내 Wi-Fi 는 이 도움말에서만 권한다**(2026-10-12). 블루투스가 닿으면 몰라도
되는 일이라 단계 글에는 넣지 않는다. 아이폰 쪽 도움말에는 Wi-Fi 에 붙을 때 뜨는
창에서 "인터넷 없이 사용", 로컬 네트워크 물음에 "허용" 을 누르라고 적는다. 둘 중
하나라도 잘못 누르면 Wi-Fi 로는 영영 안 이어진다.

이어진 뒤 맨 위 띠는 어느 길로 이어졌는지 적는다("블루투스로 이어져 있어요" ·
"Wi-Fi 로 이어져 있어요").

### 무엇이 잘못됐는지

오류는 **무엇이 잘못됐고 무엇을 누르면 되는지**를 함께 적는다. 코드나 영어를 띄우지 않는다.

## 9. 연결 상태를 어떻게 보여주나

### 맨 위 띠

화면 맨 위에 가는 띠가 있다. 어느 탭에 있든 보인다.

| 상태 | 색 | 글 |
|---|---|---|
| 연결됨 (Wi-Fi 든 블루투스든) | `success` | 이어져 있어요 |
| 길을 옮기는 중 | `warning` | 더 나은 길로 옮기는 중... |
| 찾는 중 | `textMuted` | 찾는 중... · 쓴 말 N개 보관 중 |
| 잠깐 끊김 | `textMuted` | 다시 잇는 중... |
| 못 이음 | `danger` | 아직 못 이었어요 |

**블루투스도 제대로 이어진 것이다.** 비행기에서는 이것뿐이라 "글만" 같은 단서를 달면 늘
반쪽짜리로 보인다. **이어져 있으면 띠는 3초 뒤 사라진다.** 잘 되고 있는 것을 세 시간
내내 띄워둘 이유가 없다. 끊기면 다시 내려와 무슨 일인지 말한다. 누르면 연결 상세가
열린다. 거기에는 지금 상태, 연결 방식(이름만: 블루투스·Wi-Fi·웹), 기다리는 메시지 수,
안 될 때 확인할 것(블루투스, 거리, 상대 앱, **다른 블루투스 대화 앱 끄기**)이 있다.

### 대화 화면 머리

```
┌──────────────────────────────────────────────┐
│ [캐릭터]  현지 ●                 (영화 보는 중)│
│           배터리 68%                          │
└──────────────────────────────────────────────┘
```

- 이름 옆 **점**: 초록이면 이어짐, 빨강이면 끊김. 띠가 사라진 뒤에도 이것은 남는다.
- 이름 밑 한 줄: 입력 중이면 "입력 중...", 이어져 있으면 상대 배터리, 끊겼으면
  "N분 전까지 이어져 있었어요", 한 번도 안 이어졌으면 "아직 못 이었어요". "연결됨" 은
  점과 겹쳐서 뺐다.
- 오른쪽 빈자리: **상대가 정한 상태 메시지**가 늘 떠 있다. 설정 → 이름에서 적으면 인사에
  실려 가고, 바꾸면 곧바로 다시 인사해 반영된다.
- 통화 단추는 없다. 통화가 준비 중이라 헷갈리기만 했다.

## 10. 대화 화면

### 목록은 뒤집혀 있다

가장 새 말이 0번이고 화면 아래에 붙는다(`inverted`). 그래서 도구 줄이나 키보드로 목록
키가 바뀌어도 보던 아래쪽이 그대로 따라오고, 새 말은 바닥에 있을 때만 보인다. 위로
올려 옛 말을 읽는 중이면 새 말이 와도 자리가 그대로다. 내가 보낸 말은 어디를 보고
있었든 내려간다. 위에서부터 그리고 매번 끝으로 내리던 방식은 그림이 든 말풍선과
도구 줄 여닫기가 겹치면 조금씩 못 미쳐 마지막 말이 잘렸다.

**날짜 구분선은 따로 한 칸**이다("오늘" · "어제" · "9월 17일 수요일"). 말풍선 칸 안에
같이 넣으면 뒤집힌 목록에서 순서가 뒤바뀌어 말 아래에 뜬다. 옛 말이 더 없으면 "위로
올려 옛 메시지 보기" 를 안 띄우고, 위로 올리면 저절로 더 불러온다.

시각은 같은 사람이 **같은 분** 안에 이어 말한 묶음의 마지막에만 적는다. 분이 바뀌면
앞 말에도 적힌다. 맨 마지막에만 적으면 5분 전 말과 방금 말이 같은 시각처럼 보인다.

키보드가 뜨면 두 폰 다 키보드 높이만큼 밀어 올린다(`KeyboardAvoidingView behavior="padding"`).
안드로이드는 edge-to-edge 라 창이 저절로 안 줄어서 아이폰만 그렇게 두면 키보드가 입력칸을 덮는다.

### 입력칸

```
[+] [ 메시지                       ] [🎤]
```

왼쪽에 더보기 하나만 두고, 누르면 도구 줄(콕 찌르기·이모티콘·사진·낙서)이 **아래에**
펼쳐진다. 글을 쓰기 시작하면 접힌다. 한 줄에 다 늘어놓으면 입력칸이 손가락 두 개
폭밖에 안 남았다. 입력칸은 더보기와 보내기를 뺀 나머지를 다 차지하며 말풍선 최대
폭(`BUBBLE_MAX_WIDTH`, 82%)과 거의 같다.

글이 있으면 보내기, 없으면 마이크다. **마이크를 누르면 녹음 창(`Sheet`)이 열린다.**
큰 단추를 누르면 녹음 시작(짧게 떨린다), 다시 누르면 끝. 몇 초 지났는지 보이고 20초면
저절로 끝난다. 끝나면 길이와(블루투스면) 걸리는 시간을 보여주고 보내기·버리기를 고른다.
녹음이 안 되면 왜 안 되는지 창에 적힌다. 누르고 있는 동안만 녹음하던 방식은 눌렸는지
알 수가 없어서 바꿨다.

### 사진

사진 단추를 누르면 **크기를 먼저 고른다**: 작게(800px·화질 0.5)·중간(1600px·0.8)·원본(4096px·0.9).
블루투스로 이어져 있으면 크기마다 얼마나 걸릴지 적는다(작게 30초쯤, 원본은 몇 분).
보내는 쪽·받는 쪽 모두 말풍선에 몇 퍼센트 갔는지 실시간으로 보인다. 다 받은 사진은
눌러서 화면 가득 보고, 두 손가락으로 벌려 확대하고 끌어 옮긴다. 한 번 누르거나 뒤로
가면 닫힌다.

### 콕 찌르기

받으면 폰이 짧게 한 번 떨린다. 햅틱이 아니라 진동 모터를 돌린다. 햅틱은 아이폰의
"시스템 햅틱" 설정이 꺼져 있으면 아예 안 울리고, 삼성 폰에서는 가벼운 톡이 거의 안
느껴진다. 설정 → 알림 → "콕 찔리면 떨기" 로 끌 수 있다.

### 비행기 막대

설정에서 출발·도착 시각(또는 남은 시간)을 넣으면 대화 화면 위에 비행기가 왼쪽에서
오른쪽으로 간다. 비행기는 오른쪽을 향한다. 한쪽이 넣으면 상대 화면에도 같이 뜬다(전체
길이도 같이 보낸다). 아래 "N시간 M분 남았어요" 를 누르면 "출발한 지 N시간 M분 됐어요" 로
바뀌고, 다시 누르면 돌아온다.

## 11. 설정과 도움말

설정 절은 이 순서다.

| 절 | 무엇이 있나 |
|---|---|
| 연결 | 연결 상태 자세히, 첫 실행 안내 다시 보기 |
| 이름 | 상대에게 보일 내 이름, **상태 메시지**, 상대를 뭐라고 부를까(별명) |
| 화면 | 밝기 모드, 내 캐릭터 |
| 알림 | 안 보고 있을 때 알림 방식, 보고 있을 때도 짧게 떨기, **콕 찔리면 떨기** |
| 남은 비행 시간 | 출발·도착 시각. 접이식으로 남은 시간만 넣기 |
| 음성 | 음성 메시지 저절로 틀기 |
| 대화 | 꺼내두기, 되돌리기, **비우기** |
| 이 앱에 대하여 | 도움말 |

**대화 비우기는 지우지 않고 화면에서만 감춘다.** 지우면 순번이 0으로 돌아가 다음 인사 때
상대가 전부 다시 보내 화면이 도로 채워진다. 비운 시각 전의 말은 이 폰에서만 안 보이고,
상대 화면과 꺼내둔 파일에는 남는다. 확인은 `Sheet` 로 한 번 더 묻는다.

"소리"(말하기 방식) 절과 "코드로 연결하기" 는 없다. 통화가 없고, 코드 기능은 걷어냈다.

도움말은 열두 항목이다: 어떻게 이어지나요 · 연결이 안 돼요 · 메시지가 안 가요 · 사진은
왜 오래 걸리나요 · 음성 메시지 · 콕 찌르기와 이모티콘 · 비행기와 남은 시간 · 이름과 상태
메시지 · 통화는 되나요(준비 중) · 아이폰에서 앱이 안 열려요 · 대화를 꺼내고 싶어요 ·
상대 캐릭터가 회색이에요. 기능을 바꾸면 여기도 같이 고친다.
