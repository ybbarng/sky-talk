# SkyTalk

**비행기에서 떨어져 앉은 두 사람이 인터넷 없이 대화하는 앱**

기내 Wi-Fi를 사거나 승무원을 부르지 않고, 두 사람의 휴대폰만으로 둘만의 통신망을 만든다.
글과 이모티콘, 사진, 음성 메시지를 주고받는다.

```
     안드로이드 폰                      아이폰
   ┌──────────────┐                ┌──────────────┐
   │   알리는 쪽   │◀── 블루투스 ──▶│   찾는 쪽    │
   │              │                │              │
   │  💬 글·이모티콘│◀────────────▶│  💬 글·이모티콘│
   │  📷 사진      │◀── 천천히 ───▶│  📷 사진      │
   │  🎙 음성 메시지│◀── 천천히 ───▶│  🎙 음성 메시지│
   └──────────────┘                └──────────────┘
          │                                │
          └───── 인터넷 없음. 서버 없음. ────┘
```

> 저장소와 패키지 이름은 `skywalkie` 그대로다. 2026-09-19 에 홈 화면 이름만
> SkyTalk 으로 바꿨다. 패키지까지 바꾸면 두 폰에 새 앱으로 깔려 대화가 사라진다.

## 무엇이 되나

| | |
|---|---|
| 🔵 **블루투스** | 비행기 모드에서도 두 폰이 직접 이어진다. 끊기면 스스로 다시 붙는다 |
| 💬 **메시지** | 글, 이모티콘, 콕 찌르기. 기기에 저장되어 내린 뒤에도 다시 본다 |
| 📷 **사진** | 작게·중간·원본 중에 골라 보낸다. 양쪽에 몇 퍼센트 갔는지 보인다 |
| 🎙 **음성 메시지** | 녹음 창에서 20초까지 녹음해 보낸다. 받은 쪽은 눌러서 듣는다 |
| ✈️ **비행 시간** | 출발·도착 시각을 넣으면 두 화면에 같은 비행기가 뜬다 |
| 📦 **보관** | 대화를 꺼내 두었다가 언제든 되돌린다. 공유 창으로 Google Drive 에도 올린다 |
| 🎨 **캐릭터** | 상대의 캐릭터와 상태 메시지가 이름 옆에 뜬다 |
| 🌗 **밝기** | 밝은 화면과 어두운 화면 |

**통화(음성·영상)는 아직 없다.** 블루투스로는 목소리를 나를 수 없어서 준비 중으로
두었다. 단추를 누르면 그렇게 알려준다.

## 왜 블루투스인가

**기내 Wi-Fi로는 두 폰이 서로 통신할 수 없다.** 대부분의 기내 AP가 단말끼리의 통신을 막기 때문이다. Wi-Fi Direct는 아이폰이 지원하지 않고, 블루투스 클래식은 애플 인증 부품에만 열려 있다.

처음에는 안드로이드가 핫스팟을 열고 아이폰이 붙는 방식을 주 경로로 잡았다. 그런데
**비행기 모드에서는 안드로이드가 핫스팟 메뉴를 통째로 잠근다**(2026-09-18 실기기 확인).
그래서 블루투스 저전력(BLE)이 유일한 길이 됐다. 초당 몇 KB라 느리지만, 글은 바로
가고 사진과 음성은 작게 줄여 천천히 간다. Wi-Fi 는 집에서 준비할 때만 쓴다.

자세한 검토는 [기술 선택과 근거](./docs/02-tech-decisions.md)에 있다.

> **내일 여행이라면** → [오늘 설치하기](./docs/오늘-설치하기.md) 를 보세요.

## 설치

### 안드로이드

```bash
pnpm apk && adb install -r android/app/build/outputs/apk/release/app-release.apk
```

### 아이폰

유료 개발자 계정이 없어서 **USB로 설치하고 7일마다 다시 깔아야 한다.** 절차는
[빌드와 배포](./docs/08-build-release.md)에 있다. 앱을 지우지 말고 **덮어쓰기**로
다시 깔면 대화가 남는다. 만료 3일 전부터 앱이 먼저 알린다.

## 여행 전 점검표

```
D-3   두 폰 다 비행기 모드 + 블루투스만 켜고 이어지는지 확인한다   ← 가장 중요
D-3   bitchat 같은 다른 블루투스 대화 앱은 두 폰 모두 완전히 끈다
D-1   아이폰에 앱을 다시 설치한다 (7일 시계 되감기)
D-1   대화 꺼내두기를 한 번 해본다
D-1   두 폰 완충 + 보조 배터리
당일   탑승 전에 한 번 더 이어본다
```

### 하나씩 확인할 것

```
□ 두 폰에 앱이 깔리고 열린다
□ 알림을 허용했다                              ← 안 하면 폰을 잠갔을 때 말이 안 온다
□ 이름 옆 점이 초록이다 (이어졌다)
□ 글이 오간다 (양쪽 다)
□ 콕 찌르면 상대 폰이 떨린다
□ 사진을 "작게" 로 보내면 30초 안팎에 도착하고 퍼센트가 움직인다
□ 음성 메시지를 보내고 받은 쪽에서 들린다
□ 한쪽 블루투스를 껐다 켜면 40초 안에 끊김이 뜨고 저절로 다시 붙는다
□ 앱을 껐다 켜도 대화가 남아 있다
□ 대화 꺼내두기가 파일을 만든다
```

**위 네 줄까지만 되면 여행은 된다.** 나머지는 덤이다.

## 기기 없이 돌려보기

폰이 없어도 **가상 기기 두 대**로 앱을 돌려볼 수 있다.

```bash
pnpm demo        # http://127.0.0.1:8777
```

**흉내가 아니라 진짜 앱 코드가 돈다.** 서로 찾고, 붙고, 인사하고, 말을 주고받는
것까지 다 된다. 흉내 내는 것은 셋뿐이다 — 선(브라우저 안에서 바이트를 나른다),
저장소(SQLite 대신 메모리), 화면(React Native 대신 HTML).
자세한 것은 [demo/README.md](./demo/README.md) 에 있다.

## 개발

```bash
pnpm install
pnpm expo prebuild        # 네이티브 프로젝트 만들기. 아이콘·이름을 바꿨을 때도

pnpm dev:android          # 안드로이드에 개발용 앱 설치
pnpm dev:ios              # 아이폰에 개발용 앱 설치
pnpm start                # 이미 설치했다면 이것만

pnpm verify               # 검사 + 타입 + 테스트 + 층 규칙
```

블루투스 네이티브 모듈이 들어가서 **Expo Go로는 못 돌린다.** 개발용 앱을 한 번 만들어 설치하고 그 위에서 개발한다.

필요한 것: Node 20+, pnpm 10+, **JDK 17**, **Xcode 26.2**(26.3 은 안 된다), Android SDK 35+

## 코드 구조

```
src/
├── domain/          뜻. 메시지란 무엇인가. 아무것도 import 하지 않는다
├── application/     할 일. "메시지를 보낸다"는 절차와 바깥에 요구하는 약속
├── infrastructure/  방법. 블루투스, 소켓, 데이터베이스, 녹음기
├── presentation/    화면
└── composition/     조립. 어떤 구현을 끼울지 정하는 유일한 곳
```

의존 방향은 안쪽을 향한다. `domain`은 React도 SQLite도 소켓도 모른다.
자세한 것은 [코드 구조](./docs/03-architecture.md)에 있다.
